# Phase 2 Report — AOI Input and Map Basics

Status: **accepted by the owner with follow-ups (2026-10-04)**. **Amendment:** the Phase 2.5 browser check found that deleting an AOI failed in a real browser (CORS did not allow `DELETE`); fixed in Phase 2.5, see `docs/phase-reports/phase-2.5.md` §2. The statement below that delete was verified applies to API/tests only, not to the UI. Branch `claude/geo-prospecting-foundation-hmcma4`.
Plan: `docs/phase-2-plan.md` · Design decisions: ADR-0012.

**Scope statement.** Phase 2 only lets a user define, validate, store and display an Area of Interest. **No analysis, scoring, remote-sensing, Earth Engine, 3D or scientific inference exists.** AOI responses contain geometry and bookkeeping only; a test asserts no analysis-flavoured keys appear, and another asserts the backend imports no analysis/raster/ML libraries.

## 1. What was built
| Area | Delivered |
|---|---|
| Input | Point + radius (geodesic 72-gon), rectangle, polygon (open rings accepted), upload of GeoJSON / KML / KMZ / zipped Shapefile |
| Validation (server-side, ADR-0008/0012) | geodesic area limits 0.01–25 km², radius ≤ 2.5 km, ≤ 2000 vertices, lon/lat ranges, \|lat\| ≤ 85°, antimeridian rejected, self-intersection rejected (no silent repair), single polygon only, `.prj` required for Shapefiles, GeoJSON `crs` must be WGS84 |
| Hardening | in-memory archive reads with a byte budget (declared sizes not trusted), entry/size/count caps, traversal/absolute/encrypted/nested entries rejected, DTD/entity XML refused (`defusedxml`), extension + content sniffing, filename sanitising, `MAX_UPLOAD_MB` → 413 |
| Persistence | `aoi` table extended (migration `0002`: area, vertex count, working UTM CRS, details; CHECKs for validity/area/source); `MAX_STORED_AOIS` (default 100) → 409 |
| API | `GET /aois/limits`, `POST /aois/preview`, `POST /aois`, `POST /aois/upload[?preview=true]`, `GET /aois`, `GET /aois/{id}`, `DELETE /aois/{id}` |
| Contracts | `Aoi`, `AoiDraft`, `AoiSummary`, `AoiList`, `AoiLimits` + three request types in `packages/schemas`; Pydantic/TS generated |
| Frontend | MapLibre 2D map; click-to-pick centre, two-click rectangle, click polygon (double-click finishes, Esc cancels); numeric forms for every method; upload tab; validate → summary (area, vertices, CRS, warnings) → save; saved list with select and delete; limits shown as provisional |

### Defects found by the browser/Docker checks (not by unit tests)
1. **MapLibre worker failed to load under Next/Turbopack** ("Worker failed to load"): GeoJSON overlays never drew although all unit tests passed. Fixed by serving the worker files from `public/maplibre/` (generated by `scripts/copy-maplibre-worker.mjs`) and calling `setWorkerUrl`; the frontend Dockerfile now copies `public/`.
2. Generated rings (circle, rectangle) produced a spurious "ring was not closed" warning → rings are now closed at generation; drawn polygons (documented open) produce no warning; an unclosed ring inside an uploaded file still warns.
3. Next.js injects its own `role="alert"` route announcer, which made a generic alert selector match the wrong element → our error element has `data-testid="aoi-error"`.

## 3. Not verified / limitations
- **GitHub Actions on the Phase 2 commits:** checked only after push; see the final status in the hand-over message and `TASKS.md`.
- **Real-world files:** parsers were tested with synthetic files (pyshp-written Shapefiles, hand-built KML/KMZ). Exports from QGIS/ArcGIS/Google Earth are untested (risk P-10); please supply samples.
- **CRS coverage:** reprojection is tested for EPSG:32632 → 4326 only.
- **Basemap:** the headless check used no basemap tiles. The OSM default was not exercised, and its tile policy was not re-verified (risk P-9).
- **Browsers/devices:** Chromium only; no mobile/touch testing; keyboard drawing is not supported (numeric forms are the accessible path); no screen-reader audit.
- **Performance:** a 2000-vertex AOI was validated server-side but not exercised in the UI.
- **Not built (by design):** vertex editing (redraw instead), simplification of over-limit geometry (rejected instead), multi-part AOIs, antimeridian/polar AOIs, a `project` grouping entity (ADR-0012 §12), retention/cleanup of stored AOIs.
- Working CRS (UTM, no Norway/Svalbard exceptions) is recorded but not used for any computation yet.
